# klein 融合服务（阿里云 GPU 自部署）

把 fal 上的 klein 融合搬到自己的 GPU 机器上，省掉 fal 排队和跨境网络。网页那边只把请求地址换成这台机器。

| 文件 | 作用 |
|---|---|
| `setup.sh` | 装 Python 环境、PyTorch、diffusers（阿里云 pip 镜像） |
| `download.py` | 下载权重到 `models/<名字>/`，先试魔搭再试 hf-mirror |
| `bench.py` | 在机器上测纯模型耗时（不含网络） |
| `server.py` | HTTP 服务，端口 8000，返回格式和 fal 一样 |
| `fuser.py` | 两者共用的核心：模型常驻显存、提示词编码缓存、文字长度裁短 |

## 步骤（root 用户）

```bash
cd /root/klein
bash setup.sh                          # 约 5 分钟
. .venv/bin/activate
python download.py 9b                  # 约 35GB
python bench.py --model 9b             # bf16 基准
python bench.py --model 9b --fp8       # FP8，看能快多少
python server.py --model 9b            # 开服务；终端会打印口令
```

后台常驻：`nohup python server.py --model 9b > server.log 2>&1 &`，看日志 `tail -f server.log`。

在自己电脑上检查：`curl http://<公网IP>:8000/health`。安全组要放行 TCP 8000，来源最好只填自己的公网 IP。

## 许可

klein 9B 是 FLUX 非商用许可，只能用来测试；商用要向 BFL 买授权，或者换 Apache 2.0 的 klein 4B（`python download.py 4b`）。

## 接到城市模拟页

`web/sim.html` 的配图栏：融合模型选「阿里云自部署 klein」，填 `http://<公网IP>:8000` 和服务口令（只存在本机浏览器），点「测连接」看网络来回和服务端模型。每格的说明里会写上传、服务端、纯模型、下载各花多久。

KV 版（`python download.py 9b-kv`，目录名带 kv 时自动用 KV 管线）：拼接图和参考图只在第 1 步算一次，快约 1/3。实测人物脸部明显变形，不用；正式用 9B 原精度。

网页上「阿里云 klein 9B FP8 / 9B 原精度」两项对应服务端的两种精度。显存只放得下一份，换选项时服务端整份重新加载（约 15–20 秒），之后正常速度；每格说明里会写出排队、切换各花多久。

## 实测记录（2026-10-10，乌兰察布 ecs.gn8is.4xlarge，1×L20 48GB）

纯模型（`bench.py`，576×720 输出，512 长边拼接图，256 参考图，4 步）：

| 模型 | 0 张参考图 | 1 张 | 2 张 | 显存 |
|---|---|---|---|---|
| 9B 原精度 | 2.14 秒 | 2.37 秒 | 2.57 秒 | 32.3 GB |
| 9B FP8 | 1.76 秒 | 1.95 秒 | 2.11 秒 | 23.9 GB |
| 9B-KV 原精度（画质不行，不用） | 1.51 秒 | 1.58 秒 | 1.64 秒 | 32.3 GB |

网页实测（9B FP8，北京 Mac → 乌兰察布，检查关闭）：上传 0.2 秒（35–48KB）、纯模型 1.8–2.0 秒、服务端额外 0.1–0.2 秒、下载 0.2–0.3 秒（74–109KB），浏览器本地准备 + 校色 0.3–0.5 秒，融合图约 2.6–3.0 秒后换上。测连接网络来回 183 ms（偏高，可能走了代理）。
主观画质：FP8 比 fal 上的 9B 略差，改用原精度。
网页实测（9B 原精度，新的先画之后，5 格平均）：发送前准备 0.24、上传 0.2、服务端 2.42（纯模型 2.32）、下载 0.18、校色 0.1，融合图 3.24 秒后换上，没有排队。
真实提示词有 448–512 个词元（测速里只有约 130），再加 1–3 张参考图，所以网页里的纯模型比测速表略慢。
