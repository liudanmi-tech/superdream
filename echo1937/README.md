# 回声 1937 · Demo（入住 + 第一章世界）

> 第二版设计（会自己运转的城市：托管看她过日子，随时接管，GTA 加模拟人生）见 [docs/sim-design.md](docs/sim-design.md)，评审中。

按《回声 1937 Demo 技术方案》分周实现，这一阶段做 **入住**：选身份 → 上传 3–5 张照片 → 同意与年龄 → 质检 → 角色设定图（可带修改意见重生，最多 3 次）→ 确认入住 → 后台生成 16 个动作（第一天的 4 个优先）→ 抠图、标锚点、统一身高 → 动作包完成后删除原始照片。

同时附带了第 1、2 周美术要用的两个工具：生成风格参考图、生成常驻角色的设定图和动作包。

## 最快的用法：纯本地页面（不用装任何东西）

直接双击打开 `web/index.html`（建议用 Chrome）：

1. 点右上角「设置」，填 OpenRouter API Key，点「测试连接」。Key 只保存在这台电脑的浏览器里，请求从浏览器直接发给 OpenRouter。
2. 在设置里点「生成 8 张候选」风格参考图（约 $0.3），勾选要用的。勾选的第 1、2 张会作为画风参考。
3. 关掉设置，按页面走入住流程：选身份 → 照片 → 设定图 → 动作包。

照片、设定图和动作图都存在浏览器本地（IndexedDB），刷新页面不会丢。动作包生成时请保持页面打开，关掉再打开会接着生成。抠图和锚点也在浏览器里计算，用的是"从边缘泛洪去掉浅灰背景"的方法。

改了 `content/world.json` 之后，运行 `python3 -m tools.export_world` 更新 `web/world.js`，页面才会读到新内容。

### 进入世界（第二阶段）

入住完成、第一天要用的 4 个动作生成后，点「进入世界」：

- **推进**：点「下一个时段」生成下一个时段（快速模式）。一天 6 个时段，共 7 天，到第 7 天深夜第一章结束。
- **叙事**：每个时段调用一次 Claude（设置里的「叙事模型」，也走 OpenRouter），生成 4–6 格分镜、关系变化，深夜还有日记和一位角色的视角。模型名不可用时会自动换成可用的。
- **出图**：日常画格在浏览器里拼接（场景底图 + 动作图按锚点站位、阴影、按光线调色、胶片颗粒），台词气泡叠在图上。拼接规则见下面的「拼接怎么摆人物」；拥抱、跳舞、第一次见面这类关键时刻用 Gemini 合成，每天最多 3 张，不成功就改用拼接。
- **按需生成素材**：场景底图和常驻角色第一次用到时才生成，所以每次去新地点、遇到新角色时会慢一些、多花一点。生成过的所有人共用，删除个人数据时保留。
- **决策点**：剧本里的决策点出现时故事会停住，可以接管（选一个选项，或写自己的做法），也可以交给分身按直觉选。最近 10 次选择会写进之后的提示词，让分身越来越像你。
- **自由行动**：选一个地点、写想做的事，生成 2–3 格小剧情。

- **预生成素材**：世界页面的「素材」卡片可以一键生成全部场景底图（24 张）和常驻角色的设定图与动作（85 张），约 $5、10–20 分钟，一次性。素材齐了以后，拼接格基本都是秒出。
- **出图提速**：参考图发送前缩到 1024 像素 JPEG（识别类 512 像素），上传量约为原来的十分之一；剧情边写边出格；关键时刻先用拼接格顶上，合成好后自动替换；看当前时段时后台预写下一个时段（做了选择或自由行动后会作废重写）。
- **重新拼接**：「素材」卡片里的「重新拼接已有画格」用现成素材按最新的拼接规则重画已有的拼接格，不生图；关键时刻的合成格不动。旧版场景底图会先升级（去白边、重新标地平线，每张一次识别调用，24 张约 $0.02）。
- **花费明细**：「日志」面板顶部按用途列出调用次数和花费（素材、入住、剧情、关键时刻合成、重绘、重绘检查），以及重绘成功几格、平均每格多少钱。明细存在本地，不受日志只保留 2000 条的影响；开始记之前的花费显示为"更早的（没有分类）"。
- **生图日志**：右上角「日志」记录每次调用的上传 / 等模型 / 下载耗时、每一格和每个时段的用时，可以导出（不含 API Key）。

#### 拼接怎么摆人物

- **去白边**：生图模型有时会给场景画白边或细线框，生成后从四边往里找几乎全白的行列和很细的均匀线条并裁掉。大片平涂的天空、夜空不会被裁。
- **人物大小按地平线算**：场景是眼平视角，站在地上的人眼睛都在地平线上，所以身高 ≈ 1.08 ×（脚的位置 − 地平线），越靠近镜头越大。地平线、可站的地面和座位由识别模型标出，每个光线版本单独标。没标出地平线时退回固定比例。
- **站位校验**：站位必须在地平线以下的空地上、不贴边、彼此不重叠，不够 2 个就用默认站位。
- **坐姿**：`world.json` 里动作的 `places` 限定坐姿只能在哪些地点用（高脚凳在俱乐部和餐厅，打字在报社和公寓）。卡座的动作图不画座位，场景里标出了座位才用，否则换成站立。
- **贴地**：脚下画一圈淡的投影加一小块深的接触阴影。人物调色取背景里人物所在那一块的颜色：环境暗人物也暗，暖光下偏暖。

#### 交互重绘（fal FLUX.2 klein）

拼接格对"人物和场景有接触"和"光线特殊"的格子不够真：坐不上卡座、灯光融不进去。这类格子拼好后在后台用 fal 的 FLUX.2 klein 9B 重绘一次，通过本地检查后自动替换（格子右下角显示"已重绘"）。在设置里填 fal Key、开关、每个时段最多重绘几格（默认 3）和模型名。

- **分流**：剧情模型给每格写 `interaction`（contact：none/sit/lean/hold，target，light：normal/spotlight/backlit/candle/neon/dark）。打分：有接触（含坐卡座）3 分，特殊光线 2 分（剧情写的或场景标出的聚光、逆光、暗调），夜间光线 1 分，人物所在处很暗 1 分，特写再加 1 分；2 分及以上重绘，关键时刻仍走 Gemini 合成。
- **重绘**：发拼接格加每个人这一格的动作图（灰底，只用来约束长相），指令锁定服装、镜头和人物大小，要求边缘融进场景、不要描边和边框。图片用 WebP 来回，单次约 4 秒、约 $0.015（按每百万像素 $0.01 估算，以 fal 账单为准）。
- **检查**（本地，不花钱）：画面和镜头有没有变、每个人上身的颜色有没有大变（换衣服）、四周有没有画框（有就裁掉）。重绘会给整张画面重新打光，所以比较前先把两张图的整体亮度和色调对齐：背景只看结构，衣服只看相对整张画面的颜色，整体变亮变暗、偏暖偏冷都不算。每次检查的数值都写进日志，方便按实测校准（阈值在 `fuse.js` 的 `FUSE_QC`）。不通过换一个随机种子再试一次，还不行就保留拼接格；提前重绘时没通过的格子，正式出格时不再重画。
- **秒出**：看当前时段时，后台预写好的下一个时段里要重绘的格子会先拼好、重绘好；点下一个时段直接用。做了选择或自由行动后现写的格子，先出拼接格，几秒后替换。
- **拼接本身也改进了**：场景多标家具位置和主光方向；站位落在家具上会换到旁边；动作图边缘的浅灰毛边去掉（否则重绘会画成白描边）；按主光方向给人物加明暗。旧场景点「重新拼接已有画格」会补标（每张一次识别调用）。
- **重绘后的识别检查**：本地检查通过后，再用识别模型看一眼人数、有没有多出的手脚、同一个人画了两次、悬空或站在家具上（约 1.5 秒、$0.001），不通过就重试或保留拼接格。自带凳子、桌子的动作（坐高脚凳、打字）只坐它自己画好的那把，不再要求坐到场景的家具上，否则会画出两把凳子和多余的腿。
- fal 返回 Key 不对或余额不足时，这次打开页面期间暂停重绘并提示，拼接格照常。

#### 拼接怎么构图、怎么摆多人

- **按景别构图**：远景画全身，脚踩在标出的地面上；中景从头顶裁到膝盖、近景裁到腰，画面下边截断人物，脚不出现就不会悬空。场景里看得见的地面太少（比如化妆间镜头偏高、下半部全是椅子）时，远景自动改成中景。
- **多人站成一排**：两三个人在同一深度横向排开（对话的人站得差不多远，大小才一致），保持剧情给的左右顺序，避开家具。
- **不站到家具后面**：站位会被更靠近镜头的家具（前景的椅子、桌子）挡住时换位置，因为拼接时人总画在最上层。
- **坏动作图**：抠图后还剩一整块矩形背景的动作图，这一格先用站立顶上，后台自动重新生成（"你"的动作图在动作包页面标成失败并重新排队）。

#### 融合重绘测试页

`web/fuse_test.html` 用世界里已有的拼接格，比较不同生图模型"按场景重绘"（让人坐上座位、按场景重新打光）的耗时、花费和效果，用来决定交互格的重绘用哪个模型。在主页面填好 Key、推进出一些画格后，双击打开这个页面：选 1–3 格，指令可以改，点「开始测试」，结果可以导出（不含 Key）。

还没做的：现实时间模式（每个时段按真实时间自动推进）、服务器推送、导出 / 导入素材包。

这个页面适合自己在电脑上试，Key 存在浏览器里，不要把它部署到公网给别人用。要给同事用网址访问，用下面的后端版本。

## 后端版本（部署给多人用时）

### 需要什么

一个 **OpenRouter API Key**（或 Gemini API Key）。识别和生图都走它，不填就进入模拟模式，用占位图把整条流程点通。

| 用途 | 默认模型（OpenRouter） |
| --- | --- |
| 照片质检、动作图质检 | `google/gemini-2.5-flash` |
| 设定图、动作图、风格参考图 | `google/gemini-2.5-flash-image` |

模型名放在 `.env` 里，可以换成 Pro 级图像模型，名字以 OpenRouter 模型页为准。后面做叙事时，Claude 也可以走同一个 OpenRouter Key。

### 运行（Mac）

```bash
cd echo1937
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install "rembg[cpu]"        # 可选但推荐：抠图更干净，第一次运行会下载约 170MB 模型
cp .env.example .env && open -e .env    # 填 OPENROUTER_API_KEY
python -m uvicorn app:app --port 8765   # 打开 http://localhost:8765
```

没装 rembg 时，用"从边缘泛洪去掉纯色浅灰背景"的方式抠图，头发边缘会粗一些。页面底部会显示当前用的是哪种。

## 美术预制（建议先做）

**1. 风格参考图**：所有生图都会带上它们，这是画风统一的关键。

```bash
python -m tools.style_refs          # 生成 8 张候选到 assets/style/candidates/，约 $0.3
```

挑 6–8 张满意的复制到 `assets/style/`。生图时按文件名排序，设定图取前 2 张、动作图取第 1 张，所以把最能代表画风的命名为 `01.png`、`02.png`。没有风格参考图时，设定图只按文字描述的画风生成，页面会提示。

**2. 常驻角色**（梅、伊莱、卡斯、罗南、薇薇安），完全由文字描述生成：

```bash
python -m tools.residents sheet              # 5 人各生成一张设定图候选；不满意就再跑，每次多一张
# 挑一张复制为 assets/residents/<id>/sheet.png，例如 assets/residents/mae/sheet.png
python -m tools.residents pack mae           # 用定稿的设定图生成 16 个动作
python -m tools.residents pack mae --poses stand,walk   # 只重做某几个
```

动作图写到 `assets/residents/<id>/<pose>.png`，锚点和质检结果在同目录的 `sprites.json`。

## 剧本设定集

`content/world.json` 是《回声 1937》的设定，改它不用改代码：
- **年代与开场**：时代、开场白、画风圣经。
- **人物**：三个身份及各自的服装、五位常驻角色、莉莉安失踪案。
- **地点与动作**：8 个地点及光线版本和地图坐标、16 个动作。动作的 `ratio` 是相对站立的身高比例，用于统一身高。
- **剧本与规则**：第一章 7 天的剧本节点和决策点、内容边界。

常驻角色和剧情细节是我按方案里的 7 天节点先写的一版，请编剧改。

## 验收（对应方案第 2 周）

找 5 位同事用自己的照片走一遍入住，至少 4 位认为设定图"是我"。每次生成的花费记在 `data/echo.db` 的 `image_jobs.cost_usd` 里，动作包页面也会显示当前用户已花费多少。

## 和方案相比的简化

| 方案 | 这一版 |
| --- | --- |
| Next.js + Node + BullMQ + Postgres + R2 | Python FastAPI + SQLite 简单队列 + 本地磁盘，接口和表结构按方案命名 |
| 原始照片加密存储 | 用 Fernet 加密存在 `data/users/<id>/photos/`，密钥自动生成在 `data/.photo.key` |
| 批量接口生成不赶时间的动作 | OpenRouter 没有批量接口，按优先级排队实时生成，默认并发 3 |
| 服务器推送 `/api/stream` | 前端每 2 秒轮询 `/api/onboard/status` |
| 用户身份 | 匿名 cookie，没有注册登录 |
| 长相一致不做自动比对 | 同方案：由用户在设定图阶段确认，单张动作图可以点"不像我"重生 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/onboard/role` | 选择身份（首次会建匿名用户） |
| POST | `/api/onboard/photos` | 上传 3–5 张照片 + 出生年份 + 三项同意，返回逐张质检结果 |
| POST | `/api/onboard/sheet` | 生成或重生设定图（`feedback` 为修改意见） |
| POST | `/api/onboard/approve` | 确认设定图，创建世界，启动动作包 |
| GET | `/api/onboard/status` | 当前用户的全部入住状态 |
| POST | `/api/sprites/{pose}/regen` | 某个动作"不像我"，重新生成 |
| POST | `/api/me/photos/delete` | 立即删除原始照片 |
| DELETE | `/api/me` | 删除照片、形象、动作包和世界 |

## 第二版：城市模拟（M1–M2，文字测试页）

设计见 `docs/sim-design.md`。底层是一座按回合运转的 1937 年洛杉矶：她按需求、性格和任务自己过日子，你随时可以接管。规则决定发生了什么，AI 只负责把结果画成漫画（M4 再接）。

- 打开 `web/sim.html`（双击即可，不需要任何 Key，不花钱）。
  - **下一步 / 过完这个时段 / 过完今天 / 再跑两天**：让她自己过。
  - **接管**：出现动作菜单，按钮上标着成功率、花费、占几个回合；点「这一步让她自己来」可以只代劳一步。
  - **分身遇到抉择**：全部自己选、大事问我、每次都问我。
  - 右侧是时间、状态、任务目标、线索、人物此刻在哪、任务在把她往哪儿拉、她上一步各个选项的打分。
  - **批量统计**：三种身份各跑若干局，看钱、线索、任务、缺勤、每张故事卡的触发率。
  - 进度存在浏览器里，刷新后接着玩；点「新开一局」重来。
- 数据：`content/sim.json`（时段、地点、动作、人物日程、数值）和 `content/story_*.json`（故事卡和任务）。改完运行 `python3 -m tools.export_world`，会一起生成 `web/sim_data.js`。
- 引擎：`web/sim.js`（时间、动作、检定、自主决策）和 `web/story.js`（故事卡条件、后果、任务、抉择）。浏览器和 Node 都能跑。
- 自检：`node tools/sim_check.js [局数] [天数]`，检查不报错、不卡死、主线有进展，并列出从没触发的卡。

接下来：M3 把接管界面搬进漫画版主页（地图、动作菜单、状态栏、任务和线索板），M4 把事件交给分镜和拼接/重绘出漫画，M5 补完整 7 天和结局。

## 下一阶段

第 3 周：叙事服务（每个时段一次 Claude 调用，生成分镜单）、拼接格（场景底图 + 动作图按锚点站位）、第一章剧本、观察者界面。下一阶段会先加一个生成 8 个地点场景底图的工具。
